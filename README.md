# Система учёта заявок на командировки

## Назначение

Консольное приложение для учёта сотрудников и служебных поездок. Программа позволяет создавать заявки на командировки, рассчитывать расходы, принимать решения по заявкам и сохранять данные между запусками.

## Целевая аудитория

Сотрудники организации, которые оформляют командировки, и руководители, которые рассматривают заявки. В текущей консольной версии учётные записи и разграничение прав ещё не реализованы.

## Предметная область

Сотрудник может иметь несколько заявок на поездки. Каждая заявка относится к одному сотруднику и одной поездке и содержит согласование. Для одобрения стоимость поездки не должна превышать лимит бюджета. У одного сотрудника не может быть двух одобренных поездок с пересекающимися датами.

## Возможности

- добавлять и просматривать сотрудников;
- создавать и просматривать заявки;
- искать заявки сотрудника и сортировать их по дате поездки;
- проверять даты, рассчитывать продолжительность и стоимость командировки;
- одобрять или отклонять заявки с проверкой бюджета и пересечения дат;
- просматривать количество заявок и общую стоимость одобренных поездок;
- загружать и сохранять данные в JSON-файлах.

## Основные сущности и классы

### `Employee` — сотрудник

Атрибуты: `id` — идентификатор, `name` — ФИО, `position` — должность. Конструктор `__init__()` проверяет обязательные данные. Метод `__str__()` возвращает строку для вывода сотрудника. Функции `add_employee()` и `find_employee()` работают с коллекцией сотрудников.

### `Trip` — поездка

Атрибуты: `destination` — место назначения, `purpose` — цель, `start_date` и `end_date` — даты, `travel_cost` — проезд, `hotel_cost` — проживание, `daily_allowance` — суточные за день. Конструктор проверяет даты и суммы расходов. Методы `calculate_days()` и `calculate_total_cost()` выполняют расчёты, `overlaps()` проверяет пересечение с другой поездкой, `__str__()` выводит место и даты.

### `Approval` — согласование

Атрибут `status` хранит состояние заявки: «на рассмотрении», «одобрена» или «отклонена». Метод `decide()` записывает решение для заявки, находящейся на рассмотрении. Метод `__str__()` возвращает текст статуса.

### `TravelRequest` — заявка

Атрибуты: `id` — номер заявки, `employee` — объект `Employee`, `trip` — объект `Trip`, `approval` — объект `Approval`, `budget_limit` — лимит бюджета. Метод `approve()` проверяет бюджет и пересечение дат одобренных поездок сотрудника, затем передаёт решение объекту согласования. Метод `__str__()` выводит сведения о заявке. Функции поиска, сортировки и статистики обрабатывают коллекцию заявок.

## Взаимодействие объектов

Объект `TravelRequest` содержит ссылки на объекты сотрудника, поездки и согласования. При создании заявки выбирается существующий сотрудник и создаётся поездка. Новая заявка получает статус «на рассмотрении». При одобрении учитываются стоимость поездки и уже одобренные поездки этого сотрудника. Списки `employees` и `requests` содержат объекты предметной области.

## Основные операции

### Работа с сотрудниками

Добавление сотрудника, просмотр списка и поиск по идентификатору.

### Работа с поездками

Проверка дат, расчёт дней и расходов, проверка пересечения дат двух поездок.

### Работа с заявками и согласованием

Создание и просмотр заявок, поиск по сотруднику, сортировка по дате, одобрение и отклонение, вывод статистики. При одобрении проверяются лимит бюджета и отсутствие пересечения с уже одобренной поездкой сотрудника.

## Хранение данных

Данные хранятся в файлах `data/employees.json` и `data/requests.json`. Формат JSON остался совместимым с ПР2: в заявке указан `employee_id`, данные поездки находятся во вложенном поле `trip`, а статус — в `approval`. Даты сохраняются строками формата `ГГГГ-ММ-ДД`, например `2026-10-01`.

При загрузке `storage.py` создаёт объекты `Employee`, `Trip`, `Approval` и `TravelRequest` и связывает заявку с сотрудником по `employee_id`. Если сотрудник не найден или данные повреждены, выводится ошибка. При сохранении объекты преобразуются обратно в словари, пригодные для JSON.

## Требования и установка

Нужен Python 3.10 или новее. Код приложения использует стандартную библиотеку Python. `pytest` и `flake8` нужны для тестов и проверки оформления. В PowerShell из папки проекта выполните:

```powershell
py -m pip install -r requirements.txt
```

## Запуск программы

```powershell
py main.py
```

После запуска появится меню. Для ввода дат используется формат `ДД.ММ.ГГГГ`, например `01.10.2026`.

## Тестирование

```powershell
py -m pytest -v
```

Тесты разделены по сущностям. Они проверяют атрибуты и методы объектов, связь заявки с сотрудником и поездкой, изменение статуса, ограничения по бюджету и датам, поиск и сортировку, а также восстановление связей объектов после сохранения и загрузки JSON.

## Проверка качества кода
