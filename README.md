# Система учёта заявок на командировки

## Назначение

Приложение предназначено для учёта сотрудников,
служебных поездок, заявок на командировки
и результатов их согласования.

Пользователи — сотрудники организации
и руководители, рассматривающие заявки.

В проекте сохранена консольная версия.
Веб-интерфейс реализован на Django.

## Используемые технологии

- Python 3.10 или новее;
- Django 5.2;
- Django Templates;
- Django Forms;
- SQLite;
- стандартная библиотека sqlite3;
- SQL;
- JSON;
- HTML, CSS, Bootstrap, JavaScript;
- pytest;
- flake8;
- Git.

## Предметная область

| Класс | Назначение |
|---|---|
| Employee | Сотрудник организации |
| Trip | Поездка с датами и расходами |
| TravelRequest | Заявка на командировку |
| Approval | Результат согласования |

Заявка связана с сотрудником, поездкой и согласованием.

Основные правила объектной модели:

- обязательные текстовые поля не должны быть пустыми;
- окончание поездки не может быть раньше начала;
- расходы и лимит бюджета не могут быть отрицательными;
- продолжительность включает обе даты поездки;
- стоимость включает проезд, проживание и суточные;
- одобрение невозможно при превышении бюджета;
- одобренные поездки сотрудника не должны пересекаться;
- сотрудника со связанными заявками нельзя удалить.

## Сохранённая функциональность ПР1–ПР6

Консольная версия и исходные веб-страницы работают
с JSON-хранилищем.

Доступны:

- создание и просмотр сотрудников;
- изменение сотрудников;
- удаление сотрудников без связанных заявок;
- создание, просмотр и изменение заявок;
- просмотр поездки, расходов и согласования;
- расчёт статистики;
- обработка отсутствующих объектов;
- шаблоны, формы, навигация и статические файлы.

Одобрение и отклонение заявок выполняются
в консольной версии.

## Организация хранения данных

| Файл | Назначение |
|---|---|
| data/employees.json | Сотрудники исходной версии |
| data/requests.json | Заявки с поездками и согласованиями |
| data/business_trips.sqlite | Предметная база ПР7 |
| db.sqlite3 | Служебная база Django |

SQLite-раздел показывает данные на момент
последнего импорта.

После изменения JSON через исходные страницы
или консоль необходимо обновить SQLite:

```powershell
python -m db.import_json
```

Повторный импорт заменяет содержимое предметных
таблиц актуальными данными JSON.

SQL-раздел предназначен для чтения, поиска
и статистики. Автоматическая синхронизация
двух хранилищ не реализована.

## Структура базы SQLite

### employees

| Поле | Тип | Назначение |
|---|---|---|
| id | INTEGER | Первичный ключ |
| name | TEXT | ФИО |
| position | TEXT | Должность |

### trips

| Поле | Тип | Назначение |
|---|---|---|
| id | INTEGER | Первичный ключ |
| destination | TEXT | Направление |
| purpose | TEXT | Цель |
| start_date | TEXT | Дата начала |
| end_date | TEXT | Дата окончания |
| travel_cost | REAL | Проезд |
| hotel_cost | REAL | Проживание за поездку |
| daily_allowance | REAL | Суточные за день |

Даты хранятся в формате YYYY-MM-DD.

### travel_requests

| Поле | Тип | Назначение |
|---|---|---|
| id | INTEGER | Первичный ключ |
| employee_id | INTEGER | Внешний ключ на employees.id |
| trip_id | INTEGER | Уникальный внешний ключ на trips.id |
| budget_limit | REAL | Лимит бюджета |

### approvals

| Поле | Тип | Назначение |
|---|---|---|
| id | INTEGER | Первичный ключ |
| request_id | INTEGER | Уникальный внешний ключ на travel_requests.id |
| status | TEXT | Статус согласования |

Допустимые статусы:

- на рассмотрении;
- одобрена;
- отклонена;
- отменена.

### Связи

- сотрудник — заявки: один ко многим;
- поездка — заявка: один к одному в текущей модели;
- заявка — согласование: один к одному.

Схема ограничивает повторное использование поездки
и наличие нескольких согласований одной заявки.

Наличие поездки и согласования для каждой
импортированной заявки обеспечивает скрипт импорта.

Проверка внешних ключей включается
для каждого подключения.

## Перечень SQL-запросов

| № | Имя | Назначение |
|---|---|---|
| 1 | employees | Список сотрудников |
| 2 | trips | Список поездок |
| 3 | approved_requests | Отбор по статусу |
| 4 | trips_by_destination | Поиск направления |
| 5 | requests_details | Связанные данные всех заявок |
| 6 | employee_requests | Заявки сотрудника |
| 7 | counts | Количество записей в таблицах |
| 8 | approved_totals | Количество и стоимость одобренных поездок |
| 9 | requests_by_employee | Группировка по сотрудникам |
| 10 | requests_by_status | Группировка по статусам |
| 11 | employees_above_threshold | Фильтрация групп через HAVING |
| 12 | available_employees | Сотрудники без одобренной поездки на дату |

Используются SELECT, WHERE, ORDER BY,
JOIN, LEFT JOIN, COUNT, SUM, COALESCE,
GROUP BY, HAVING и NOT EXISTS.

Пользовательские значения передаются
через параметры ?, отдельно от SQL-команды.

## Получение данных в Django

Последовательность обработки:

1. Django получает HTTP-запрос.
2. Форма проверяет пользовательские параметры.
3. Представление вызывает fetch_all().
4. Модуль database.py выполняет SQL.
5. SQLite возвращает строки sqlite3.Row.
6. Представление подготавливает контекст.
7. Шаблон отображает результат.

Обращение к значениям результата выполняется
по именам столбцов.

Пустые результаты обрабатываются в шаблоне
через блок empty.

## Установка

Команды выполняются в PowerShell
из папки с manage.py.

Создание окружения:

```powershell
python -m venv venv
```

Активация:

```powershell
.\venv\Scripts\Activate.ps1
```

Установка зависимостей:

```powershell
python -m pip install -r requirements.txt
```

Создание служебных таблиц Django:

```powershell
python manage.py migrate
```

Создание предметной базы и импорт:

```powershell
python -m db.import_json
```

Проверка импорта:

```powershell
python -m db.check_database
```

## Запуск

Веб-приложение:

```powershell
python manage.py runserver
```

Главная страница:

http://127.0.0.1:8000/

SQLite-раздел:

http://127.0.0.1:8000/sql/employees/

Консольная версия:

```powershell
python main.py
```

## Проверки

Конфигурация Django:

```powershell
python manage.py check
```

Тесты объектной модели:

```powershell
python -m pytest -v
```

Проверка стиля:

```powershell
python -m flake8 . --extend-exclude=venv
```

Проверка SQLite:

```powershell
python -m db.check_database
```

Последняя команда проверяет:

- соответствие количества записей исходному JSON;
- отсутствие нарушений внешних ключей;
- выполнение всех 12 запросов.

Существующие тесты проверяют сотрудников,
поездки, связи объектов заявки, согласование,
бюджет, пересечение дат, поиск и сортировку.

В браузере дополнительно проверяются страницы,
формы, навигация, пустые результаты и поиск.
