# Система учёта заявок на командировки

## Назначение проекта

Приложение предназначено для учёта сотрудников,
служебных поездок, заявок на командировки
и результатов их согласования.

Целевая аудитория — сотрудники организации
и руководители, рассматривающие заявки.

В проекте сохранена консольная версия.
Веб-интерфейс реализован на Django.

В ПР6 веб-страницы переведены с формирования HTML
в Python на систему шаблонов Django.

## Предметная область

В проекте используются четыре основных класса:

| Класс | Назначение |
|---|---|
| Employee | Сотрудник организации |
| Trip | Поездка с датами и расходами |
| TravelRequest | Заявка на командировку |
| Approval | Результат согласования заявки |

Заявка содержит ссылки на сотрудника, поездку
и согласование.

Основные правила:

- ФИО, должность, направление и цель обязательны;
- дата окончания не может быть раньше даты начала;
- расходы и лимит бюджета не могут быть отрицательными;
- продолжительность включает обе даты поездки;
- общая стоимость включает проезд, проживание
  и суточные за все дни;
- одобрение невозможно при превышении бюджета;
- одобренные поездки сотрудника не должны
  пересекаться по датам;
- сотрудника со связанными заявками нельзя удалить;
- при редактировании заявки сохраняются номер и статус;
- изменение одобренной заявки требует повторной
  проверки бюджета и пересечения дат.

## Возможности веб-интерфейса

### Главная страница

Отображает:

- количество сотрудников;
- общее количество заявок;
- количество одобренных заявок;
- стоимость одобренных поездок.

### Сотрудники

Реализованы:

- список сотрудников;
- карточка сотрудника;
- список связанных заявок;
- создание сотрудника;
- редактирование ФИО и должности;
- удаление сотрудника без связанных заявок.

Удаление выполняется через POST-запрос
с подтверждением в браузере.

### Заявки

Реализованы:

- список заявок по дате начала поездки;
- карточка заявки;
- создание заявки;
- редактирование заявки;
- выбор сотрудника;
- отображение дат и продолжительности;
- отображение расходов и лимита бюджета;
- отображение статуса согласования.

Новая заявка получает статус «на рассмотрении».

Одобрение и отклонение выполняются
в консольной версии.

Регистрация, авторизация и разграничение
прав доступа пока не реализованы.

## Страницы и маршруты

| URL | Назначение | Имя маршрута |
|---|---|---|
| `/` | Статистика | `homepage:index` |
| `/employees/` | Список сотрудников | `employees:list` |

| `/employees/<int:employee_id>/` | Карточка сотрудника | `employees:detail` |
| `/employees/<int:employee_id>/edit/` | Изменение и удаление сотрудника | `employees:edit` |

| `/requests/new/` | Создание заявки | `trip_requests:create` |

| `/requests/<int:request_id>/edit/` | Изменение заявки | `trip_requests:edit` |

В приложениях объявлены пространства имён
через `app_name`.

Ссылки формируются тегом `{% url %}`.
Перенаправления и обратные ссылки используют
`redirect()` и `reverse()`.

## Архитектура веб-части

Обработка страницы:

```text
URL → view → context → template → HTML
```

Представления загружают данные, вызывают
предметную логику и передают объекты в шаблоны.

Шаблоны отвечают за отображение данных.

Расчёты стоимости, продолжительности и проверки
бизнес-правил остаются в Python-классах.

Функции `page()` и `form_page()` удалены.
HTML-страницы больше не собираются
из Python-строк.

## Шаблоны Django

### Базовый шаблон

`templates/base.html` содержит:

- общий HTML-каркас;
- блок `title`;
- блок `content`;
- подключение навигации;
- подключение Bootstrap и собственного CSS;
- подвал;
- подключение JavaScript.

Дочерние страницы используют
`{% extends "base.html" %}`.

### Включаемые шаблоны

Через `{% include %}` подключаются:

- общая навигация;
- карточка сотрудника;
- статус заявки.

Во фрагменты передаются необходимые данные
через `with`.

### Контекст

Данные передаются через `render()`.

Основные переменные:

- `employees`;
- `statistics`;
- `employee`;
- `employee_requests`;
- `travel_requests`;
- `travel_request`;
- `form`;
- `title`;
- `back_url`;
- `can_delete`.

### Циклы и условия

`for` используется для вывода коллекций.

`empty` выводит сообщение при отсутствии элементов.

`if`, `elif` и `else` используются
для отображения статусов и кнопки удаления.

### Фильтры

Используются:

- `length` — количество элементов;
- `default` — запасное значение;
- `date` — форматирование дат;
- `floatformat` — форматирование денежных сумм.

Текстовые данные по умолчанию
автоматически экранируются Django.

## Статические файлы

Расположены в `homepage/static/homepage/`.

- `css/style.css` — собственное оформление;
- `js/main.js` — текущий год и подтверждение удаления;
- `img/logo.svg` — логотип.

Файлы подключаются через
`{% load static %}` и `{% static %}`.

Bootstrap подключается через CDN
и требует доступа к интернету.

## Формы

`EmployeeForm` содержит ФИО и должность.

`TravelRequestForm` содержит выбор сотрудника,
данные поездки, расходы и лимит бюджета.

Для форм используется общий шаблон `form.html`.

POST-формы содержат `{% csrf_token %}`.

Проверки выполняются Django Forms
и классами предметной области.

После успешного сохранения выполняется
перенаправление на страницу объекта.

## Хранение данных

Предметные данные находятся в:

- `data/employees.json`;
- `data/requests.json`.

`storage.py` преобразует JSON
в объекты Python и обратно.

Даты сохраняются в формате `ГГГГ-ММ-ДД`.

При загрузке заявка связывается
с сотрудником по `employee_id`.

Данные поездки и согласования хранятся
внутри записи заявки.

Предметная модель пока не использует Django ORM.
Настроенная SQLite предназначена
для служебных таблиц Django.

## Обработка ошибки 404

При отсутствии сотрудника или заявки
представление возвращает шаблон `404.html`
со статусом 404.

Для неизвестных маршрутов настроен:

```python
handler404 = "homepage.views.page_not_found"
```

При `DEBUG = True` неизвестные маршруты
показывают техническую страницу Django.

Пользовательский обработчик неизвестных маршрутов
применяется при `DEBUG = False`.

## Установка

Команды выполняются в PowerShell
из папки с `manage.py`.

Создать окружение:

```powershell
python -m venv venv
```

Активировать:

```powershell
.\venv\Scripts\Activate.ps1
```

Установить зависимости:

```powershell
python -m pip install -r requirements.txt
```

Применить служебные миграции:

```powershell
python manage.py migrate
```
