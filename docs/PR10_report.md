# Административная панель и ORM в проекте командировок

Цель ПР10 — настроить Django Admin и закрепить работу с ORM на существующем
проекте. Требования Roomly адаптированы к сотрудникам, поездкам, заявкам и
согласованиям согласно примечанию раздела 7.3 методички.

## Выполненные изменения

Зарегистрированы четыре модели в административной панели. Добавлены русские
названия приложений, моделей и связей, столбцы, поиск по связанным полям,
фильтры, сортировка и страницы по 10 строк. Inline показывает связи и позволяет
перейти к отдельной форме. Формы Trip, TravelRequest и Approval проверяют
лимит бюджета и пересечения одобренных поездок при соответствующих изменениях.

Employee получил уникальный slug и get_absolute_url. Миграция добавляет поле,
заполняет адреса существующих записей через RunPython и включает уникальность.
Старые адреса по ID сохранены. Вторая миграция локализует метаданные моделей.
Статусы Approval уже использовали TextChoices в ПР9 и сохраняются без преобразования.

TravelRequestQuerySet объединяет повторяющиеся условия по статусу и дате,
получение связанных моделей и выборку словарей. Методы используются в
представлениях и общих запросах. Табличный список использует annotate с F и
values; карточка и обычный список — select_related. Статистика дополнена
aggregate с Count и Q по всем четырём статусам. Группировка по сотрудникам,
статусам и фильтр групп по количеству сохранены.

Контекстный процессор передаёт название сайта и число сотрудников в подвал.
GeneratedField не добавлен: в пункте 16 допускается демонстрация другого
изменения модели с миграцией. Стоимость поездки продолжает вычисляться по расходам.

## SQL и результаты проверки

Подключён django-debug-toolbar 6.2.0 для локальной отладки.
Настройка соответствует [официальной инструкции](https://django-debug-toolbar.readthedocs.io/en/latest/installation.html).
Проверка выполнена на локальной базе через Django Client с включённой панелью
и CaptureQueriesContext. Ответы HTTP 200 и наличие HTML панели подтверждены.

| Страница | SQL запросов | Назначение |
|---|---:|---|
| `/requests/` | 3 | COUNT списка, SELECT страницы с JOIN, COUNT сотрудников общего контекста |
| `/requests/ID/` | 2 | Заявка с JOIN сотрудника, поездки и согласования; общий контекст |
| `/sql/requests/` | 3 | Словари списка с JOIN; одобренные согласования; общий контекст |
| `/employees/profile/slug/` | 3 | Сотрудник; его заявки с JOIN; общий контекст |
| `/sql/statistics/` | 10 | Общие счётчики, агрегаты и группы; общий контекст |

Тест `test_relations_query_count_and_zero_groups` подтверждает один запрос
при чтении связанных атрибутов списка. Словарная выборка также проверена одним
SQL в `test_queryset_methods_rows_and_status_totals`.
Визуальная работа боковой панели в браузере требует ручного просмотра:
автоматизированный браузер в этой сессии недоступен. Скриншоты не подменялись макетами.

Проверены занятость сотрудника по обеим границам поездки, освобождение после
отмены, поиск, сортировка, пагинация, неверный ввод и 404, защита удаления,
CRUD, перенос ПР7, миграция существующих сотрудников и формы админки.
После миграций сохранены 4 сотрудника, 3 поездки, 3 заявки и 3 согласования.

## Подготовка к сдаче

Проверки `manage.py check`, `makemigrations --check --dry-run`, 18 Django-тестов,
9 прежних pytest-тестов и flake8 завершились успешно.

Команды проверки приведены в README. Для отчёта преподавателю сделайте снимки
админки, связанных записей, фильтрации списка, статистики, SQL панели и результатов тестов.

аккаунте. В Git сохранены две контрольные точки ПР10: исходное состояние
и настройка админ-панели с проверкой ORM. История доступна через `git log --oneline`.

и локальная база с учётной записью. Отправка в удалённый репозиторий не выполнялась.
