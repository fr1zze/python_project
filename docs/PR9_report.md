# Отчёт по практической работе №9

Тема: «Модели Django, связи и операции с базой данных через ORM».
Дисциплина: «Технологии разработки приложений на базе фреймворков».
Проект: система учёта заявок на командировки.
Дата выполнения: 7 ноября 2026 года.
Образовательная организация, группа, ФИО студента и вариант:
заполняются студентом (в запросе не указаны).

Цель — описать предметную область моделями Django, освоить миграции и
операции ORM, перевести существующие страницы с JSON/sqlite3 на ORM.

В существующих приложениях созданы модели `Employee`, `Trip`,
`TravelRequest`, `Approval`. Для текста используются `CharField`/`TextField`,
для дат — `DateField`, денег — `DecimalField`, статуса — `TextChoices`.
Заявка связана с сотрудником через `ForeignKey(PROTECT)` и с поездкой через
`OneToOneField(PROTECT)`. Согласование связано с заявкой через
`OneToOneField(CASCADE)`. Указаны обратные связи `related_name`.
Сохранены расчёт стоимости с включительными датами, защита бюджета,
проверка пересечений одобренных поездок и запрет удаления сотрудника с заявками.

Созданы и применены начальные миграции приложений `employees` и
`trip_requests`. Выбрана отдельная база Django `db.sqlite3` и перенос
из базы ПР7 `data/business_trips.sqlite`. Источник открыт только для чтения,
сохранены резервные копии исходной базы и базы Django до миграций.
Команда `python manage.py import_pr7` атомарно переносит и сверяет поля,
первичные и внешние ключи. Перенесены 4 сотрудника, 3 поездки, 3 заявки,
3 согласования. Повторный запуск создал 0 записей. Конфликтующие значения
приводят к откату, а не перезаписи пользовательских изменений.

Представления сотрудников, заявок, главной страницы и отчётов `/sql/`
получают данные через ORM. Реализованы создание, чтение, изменение,
защищённое удаление сотрудников, работа со связями через `select_related`,
поиск по строковому полю и нескольким полям с `Q`, фильтрация по сотруднику,
дате, статусу и направлению, `exclude`, сортировка по белому списку полей,
агрегаты `Count`/`Sum`, группировка `annotate` и фильтрация групп.
Список заявок разбит `Paginator` на страницы по 10 записей с сохранением
параметров поиска, фильтров и сортировки. Ошибочные параметры показываются
в форме, отсутствующие объекты возвращают 404. В README приведён каталог
20 применяемых ORM-выражений и команды выгрузки/загрузки fixture.
